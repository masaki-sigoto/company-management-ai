# コミット・レビュールール

## コミットルール

1. **1作業 = 1コミット**: 論理的に独立した変更ごとにcommitすること
2. **大きなタスクは分割**: 複数ファイルにまたがる変更も、意味のある単位で分割commit
3. **コミットメッセージ**: 変更の「何を」「なぜ」を簡潔に記述

## Push前レビュー（必須）

1. **Codex CLIでレビューを実施**してからpushすること
2. レビュー指摘があれば修正し、再度レビューを通すこと
3. レビュー観点:
   - セキュリティ（脆弱性、秘密情報の漏洩）
   - パフォーマンス（不要な再レンダリング、N+1クエリ）
   - 可読性（命名、構造、コメント）
   - テスト品質（カバレッジ、エッジケース）

## サブエージェント委任ルール

1. **メインエージェントはPMとして振る舞う**こと
2. 実装作業はTask toolでサブエージェントに委任すること
3. メインが直接実装するのは軽微な修正のみ
4. サブエージェントの成果物は必ず確認してから統合すること
